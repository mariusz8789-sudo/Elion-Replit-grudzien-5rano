# Genesis Model–Observation Candidate Review

**Status:** forensic selection only; no bridge implemented  
**LIVE baseline:** `719f2a8`  
**Decision rule:** an existing Genesis model must predict the same observable represented by an independent, source-pinned dataset. Input equal to observation is not validation.

## Executive decision

The strongest current candidate is:

> **Genesis `nuclear-semf` binding-energy prediction → AME2020 evaluated atomic-mass table (`mass_1.mas20`)**

This candidate is stronger than Kepler → JPL Horizons for the first model-versus-observation proof because the existing SEMF model takes only nuclear composition `(Z,N)` and predicts binding energy, while AME2020 provides evaluated atomic masses, binding energy per nucleon and uncertainties in a stable ASCII table. The existing local nuclide chart is not sufficient by itself: it contains selected half-life/decay metadata and does not contain the raw AME2020 binding-energy artifact.

This is **not yet BUILD NOW**. It is `CANDIDATE_FOR_ADMISSION / BUILD LATER` pending a contract-only fixture, exact unit transformation, treatment of estimated values, licence/terms review and no-network replay proof.

## Why SEMF → AME2020 is compatible

The existing backend registry defines `nuclear-semf` with inputs `protonNumber` and `neutronNumber` and outputs `bindingEnergy`, `bindingPerNucleon` and `massNumber`, with units MeV. Its declared formula is the semi-empirical mass formula and its assumptions explicitly state that shell effects are omitted. The model is therefore a prediction of a nuclear observable conditional on `(Z,N)`, not a replay of a measured value.

The AMDC official page identifies the AME2020 files, including `mass_1.mas20` for atomic masses, and states that the published AME2020 papers are the scientific citation for work using the electronic files [1]. The raw `mass_1.mas20` file contains columns for mass excess, binding energy, binding-energy uncertainty, beta-decay energy and atomic mass, including the header that defines units and estimated-value markers [2]. This makes it possible to construct a lossless raw fixture and a transparent normalized observation, provided the transform is specified and estimated records are not silently treated as experimental measurements.

## Admission requirements before BUILD NOW

1. Pin the exact AME2020 raw file bytes and SHA-256 in a repository fixture.
2. Record URL, retrieval context, file/date/version, cited publication, units, observable definition, uncertainty, estimation markers and licence/terms status.
3. Define the transformation from AME atomic-mass fields to binding energy or binding energy per nucleon, including constants and unit conversion.
4. Select a small preregistered set of nuclides, including at least one non-magic nucleus and one shell-effect-sensitive nucleus, without tuning the model after seeing the errors.
5. State whether the comparison is against binding energy or binding energy per nucleon; do not mix them.
6. Exclude or separately label AME entries marked estimated (`#`) rather than treating them as measured ground truth.
7. Use the existing Experiment Fabric, Evidence Pack and Replay. Do not create a second observation or evidence system.
8. Replay must use the pinned raw fixture and must never refetch the network.
9. Define bidirectional tolerance with source uncertainty and a declared model-error policy. A large discrepancy is a model result, not a failed source.
10. Add negative tests for changed raw bytes, changed SHA-256, changed nuclide, changed units, changed transform version and estimated-vs-experimental classification.

## Kepler/JPL assessment

JPL Horizons is a high-quality reference system with a documented API. Its API supports observer, vector and element ephemerides and requires explicit parameters such as target, center, time range, time scale, reference frame and units [3]. This is technically pinable and valuable, but the current Genesis Kepler graph predicts period, circular-orbit speed and a relative tidal ratio from mass and radius. It does not predict the Horizons observer quantities or a complete propagated state vector. A future bridge would therefore require either a thin, scientifically justified observation operator or a new output contract. It should not be presented as direct sensor validation.

## NOAA/Lorenz assessment

NOAA GHCNh is an official hourly/synoptic dataset of fixed land-station observations and replaces ISD [4]. It contains temperature, wind, pressure, precipitation and related station variables. The current Lorenz model produces dimensionless dynamical-system state variables, so there is no honest one-to-one observable mapping. The dataset is valuable for a future weather/chaos model only after an actual observation operator and model admission; it is not a candidate for the current Lorenz route.

## CTO decision

`nuclear-semf → AME2020` is the **next candidate to validate**, but not yet authorized for implementation. The next step is a contract-only AME2020 fixture/admission review. If raw bytes, source terms, uncertainty semantics, estimated-value handling and transform are all accepted, the minimal path is:

```text
AME2020 raw fixture
  → normalized observation
  → existing SEMF run
  → per-nuclide comparison
  → existing Evidence Pack
  → no-network Replay
  → MATCH / DRIFT / BLOCKED
```

Atom-Bohr G3 remains blocked and untouched. No USGS live adapter, NOAA adapter, GIS, instrument integration, new solver, new domain or second Evidence/Replay system is authorized.

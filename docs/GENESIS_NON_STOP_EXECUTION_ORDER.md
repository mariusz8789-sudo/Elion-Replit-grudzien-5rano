# Genesis Non-Stop Execution Order

**Status:** ACTIVE CTO EXECUTION CONTRACT  
**Source of truth:** `manus/high-fidelity-epidemic-digital-twin` LIVE branch.

## Mission

Genesis is advanced as one Scientific Discovery OS, one real milestone at a time. Finishing a milestone never means stopping when the next safe, valuable, executable gap exists.

`DONE ONE → IMMEDIATELY START NEXT`

The order is not permission to build speculative features. It is a sequencing rule that preserves scientific honesty, architectural reuse and verified delivery.

## Mandatory loop

`FIND REAL GAP → DESIGN MINIMAL FIX → IMPLEMENT → TESTS → TYPECHECK → LINT → PRODUCTION BUILD → CHROMIUM DESKTOP → CHROMIUM MOBILE → CI → CLEAN GIT → COMMIT → UPDATE ROADMAP → NEXT GAP`

A milestone is not green because a card or parser phrase exists. It is green only when the model, execution, provenance, visualization/evidence behavior and limitations are actually verified.

## Architecture order

`REUSE EXISTING > EXTEND > THIN ADAPTER > NEW CODE`

Do not create a second router, Experiment Fabric, Evidence system, Replay system, WorldState, renderer or CityWorld. LIVE remains the source of truth. Claude/Gemini materials are `REVIEW → ADAPT → INTEGRATE` only when the diff is compatible and independently verified.

## Honesty contract

Every result is labeled with its epistemic status: `ESTABLISHED`, `MODEL`, `APPROXIMATION`, `EDUCATIONAL`, `HYPOTHESIS`, `NOT_MODELED` or `UNSUPPORTED`. AI may parse, plan and explain; the registered model calculates; Genesis validates, visualizes, documents and replays.

Absent data is `NOT_MODELED`. A future date is not a forecast. `HISTORY`, `MODELLED_FUTURE` and `SPECULATIVE` must remain visually and semantically distinct. The parked Spacetime Navigator remains a specification until it has a valid time-coordinate model, scenario protocol, uncertainty semantics, single-renderer route, replay strategy and full quality gate.

## Branch and package policy

All accepted changes are committed and pushed directly to the configured LIVE GitHub branch. No ZIP deliverables are produced. External packages are never auto-merged and must include inventory, source/license/runtime metadata, tests, rollback information and an explicit `ACCEPT`, `ADAPT`, `PARK` or `REJECT` decision.

## Stop conditions

Stop only at a real blocker: missing scientific model, missing required data, safety issue, architecture conflict, legal/licensing uncertainty or inability to validate safely. Document the blocker with `BLOCKED`, `NOT_MODELED` or `VERIFY_REQUIRED`, then continue with the nearest independent milestone.

## Definition of done

A milestone is complete only after implementation, tests, TypeScript, lint, production build, Chromium desktop, Chromium mobile, GitHub Actions, clean working tree, commit and roadmap synchronization. After that gate, begin the next approved milestone without waiting for a separate approval.

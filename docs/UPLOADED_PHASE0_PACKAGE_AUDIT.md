# Uploaded Phase 0 package audit

## Decision

The uploaded **17-file / 47-test** Phase 0 package was reviewed as reference material only. **No uploaded source code, tests, metadata entries, solver, adapter, GIS capability, City3D integration, or data record has been imported into Genesis.** The package contains several sound Phase 0 ideas, but the live Genesis branch already provides stronger, integrated equivalents for provenance, persistence, evidence admission, replay and module compatibility.

> A robust contract from a separate package is not automatically a compatible Genesis contract. Replacing a live, tested provenance path with a parallel one would reduce auditability rather than improve it.

## Evidence reviewed

The uploaded material proposed runtime validators; `SourceArtifact` and `HazardInput` contracts; canonical SHA-256 fingerprints; an in-memory `ImmutabilityGate` and `ProvenanceChain`; a dry registry containing seven datasets; exports; and focused tests. The review compared those claims with the current [hazard contracts](../packages/frontend/src/core/hazard/contracts.ts), [fingerprints](../packages/frontend/src/core/hazard/fingerprint.ts), [immutable provenance store](../packages/frontend/src/core/hazard/hazardProvenanceStore.ts), [replay fence](../packages/frontend/src/core/hazard/hazardReplay.ts), [module registry](../packages/frontend/src/core/hazard/hazardModuleRegistry.ts), and [dataset-governance registry](../packages/frontend/src/core/hazard/datasetRegistry.ts).

## Why the dry registry remains narrow

The uploaded registry labels all its records `liveFetch: false`, but it nevertheless introduces new source families and terminology such as observed ingestion, scenario triggers, spatial joins and map context. Genesis deliberately permits none of those operations under the current governance boundary. The approved registry remains metadata-only for one future earthquake candidate and blocks every adapter with `METADATA_ONLY`, `LICENSE_REVIEW_REQUIRED`, `NO_ADAPTER_IMPLEMENTED`, and `SPATIAL_POLICY_REVIEW_REQUIRED`; see [Dataset governance registry](./DATASET_GOVERNANCE_REGISTRY.md).

This is a policy distinction, not a criticism of the listed sources. Adding catalogue entries can imply future authorized pathways and therefore requires separate source, terms, spatial-reference, mapping and intended-use review before it becomes a repository change.

## Maintained system boundaries

The decision preserves the existing single City3D renderer and CityWorld; the **SCENARIO / SYNTHETIC / NON_OPERATIONAL** Earthquake demonstrator; no live data, GIS, second hazard, cascades or impact claims; and no changes to EpidemicCitySimulation, routing, hospitals, discovery or replay. No network request was made during this audit.

## Safe next action

No code import follows from this package. The next material engineering action should be selected only after a separate product and governance decision authorizes one of the currently blocked domains. Until then, the only justified work is maintenance of existing CI/documentation or independent audit of a concrete, non-overlapping proposal.

# Genesis advantage and delivery plan

Genesis should first prove one auditable research question from sources to a reproducible, scoped report. Its strongest proposed advantage is the quality of that evidence chain, not the number of engines, agents or rendered worlds. This document gives the product owner, Claude, Sol and Astra an implementation order and evidence requirements. It authorizes no deployment, purchase, clinical claim or change to scientific acceptance thresholds.

### GLP-1R scientific boundary

Preserve all existing preregistrations, gate fingerprints and sealed artifacts. `glp1r-d144-expanded.sealed.json` reports combined-arm MAE 1.0118 against frozen MAX_MAE 1.0: a failed gate. `glp1r-d152-endpoint-scope.sealed.json` later establishes 320 functional-agonism rows, 206 compounds and 89 scaffolds, with train/calibration/test 193/74/53 and sufficiency `SUFFICIENT`. That is a row-count/split result only: no new model was trained or gate passed, and the recombinant heterologous assay systems do not establish native tissue pharmacology.

The next scientific step is a preregistered functional-subset model validation under the unchanged gate, with leakage and assay independence checks. The target registry still has ABL1 1IEP only in inspected main; Sol's Vina example is ABL1, not GLP-1R. GLP-1R needs its own vetted structure, preparation and reference case. Pathway/expression data require independent source-backed contracts; a tissue illustration cannot fill that gap. `molecularMission.mjs` correctly permits `NO_WINNER` when efficacy cannot be evaluated. A failed model plus an auditable dossier can pass an engineering demonstration while failing candidate readiness.

## Scale plan using the existing control plane

The following sizes and limits are proposed pilot caps for measurement, not measured capacity, provider quotas or purchased infrastructure. Owners should lower them if runtime evidence requires it. No pricing estimate is asserted; current provider prices, regional availability and actual workload costs were not researched.

| Stage | Data envelope | Compute and queue | Storage and promotion gate |
|---|---|---|---|
| First 7 days | One bounded question; up to 100 retrieved metadata records and 20 licensed text items; existing selected molecule/assay pins | One active costly computation per selected worker process; small CPU-first reference cases; record timeout and cost units | Existing DB owns identity/state; immutable source/input/output manifests. Enforce a proposed 1 GiB raw-artifact budget per pilot run, with explicit stop/exclusion reasons |
| By 14 days | Proposed bounded load fixture: 10 runs, at most 1,000 metadata records total; frozen cache rather than repeated provider pulls | Measure queue wait, duration, peak RSS, CPU-seconds, output bytes, failure/retry counts and rate limits. Exercise cancellation and worker loss before allowing concurrent consumers | Choose approved object storage if current artifact retention is insufficient; DB stores refs/hash/size/access policy. Run backup/restore and clean-environment replay |
| By 30 days | Admit more runs only from observed demand, rights clearance and measured budgets; dataset updates create new snapshots | Durable dispatch leases and per-project/principal aggregate budget; bounded retries and tenant fairness before horizontal scaling. Keep existing engine groups | Publish tested workload envelope and measured cost per completed/blocked run. Separate retention policy for private data, licensed text, raw computation and regenerable indexes |

For each worker group, measure arrival rate `lambda` in jobs/second and mean service time `s` in seconds. A first capacity estimate is `ceil(lambda * s / u)` execution slots, with proposed utilization target `u <= 0.7`; use tail latency and mixed-job tests to check it, not this formula alone. CPU demand is measured CPU-seconds per job; memory is concurrent measured peak RSS plus explicit headroom. Artifact storage is retained runs times mean retained bytes plus source snapshots, indexes and backup copies. Reserve maximum permitted run cost before dispatch, reconcile measured usage, and stop before exceeding the customer's accepted budget.

Preserve `jobs`, `science_runs`, existing dispatch contracts and ResearchRun IDs. Reuse Sol S9 `workerInfrastructureContract.mjs`; before more than one consumer can claim jobs, implement its shared backend with an atomic claim/lease with a fencing token, bounded lease renewal and crash reconciliation. At-least-once delivery must be safe through execution-id dedupe and idempotent publication; do not promise exactly-once computation across failures. Retry transient transport failures with bounded backoff and jitter; licence, schema, scientific gate and invalid-input failures need review or changed inputs, not blind retries. A cancellation retains partial outputs and records whether the running solver actually stopped.

Keep large artifacts outside queue payloads: queue immutable object IDs plus hashes, protocol identity and resource budget. Enforce auth on object reads and verify checksums before use. A source cache key includes provider, query/accession, release, schema and transformation version; new source bytes never overwrite a frozen run. Do not put third-party full text into logs, model prompts or customer bundles unless its intended-use decision permits that operation. Handle expiry/deletion through audited access and retention rules; append-only history is not a reason to retain private content forever.

CPU first: RDKit descriptors, bounded Vina, the canonical H2 calculation and dataset checks have existing CPU paths. Preserve separate admet and pymeep environments; shared ADMET/toxicity implementation is not an independent second scientific method. GPU adoption is conditional on one admitted workload showing a measured bottleneck and a reproducible CPU/GPU comparison under preregistered tolerance. Check device memory, driver/runtime/model-weight licences and workload cost first. A GPU cannot repair a failed biological validation gate. Do not buy a standing GPU fleet for a future hypothetical model.

The minimal execution boundary remains allowlisted scientific inputs, no arbitrary shell/code, non-root worker identity, restricted filesystem, bounded temporary storage and explicit egress. Container packaging and HTTP token auth alone do not prove isolation against hostile code. Reuse Sol S10 `scientificSandboxContract.mjs`; if generated Python execution becomes essential, implement its backend as a separate security-reviewed admission milestone with resource/network/secret isolation tests and a kill path; it is outside the first vertical.

## Five proposed advantages and their proof obligations

These are product hypotheses, not claims of market uniqueness or verified superiority over another product. A competitive comparison requires the same task, inputs, budget and independently inspectable outcomes.

| Proposed advantage | Concrete customer benefit | Minimum proof and limit |
|---|---|---|
| Evidence and Replay | A reviewer can inspect what actually ran and reproduce the delivered result | One export resolves question, preregistration, raw output, environment, Evidence approval and a positive Replay receipt; tamper/drift and missing-runtime examples remain visible. Hash integrity is not organizational authenticity or scientific validity |
| Self-falsification | Negative and inconclusive results prevent wasted follow-up work | Freeze predictions first; deterministic outcomes for a met criterion, failed critical criterion and unresolved result; show no post-result threshold edit. Protocol-scoped confirmation is not universal truth |
| Claim to source | Every important sentence can be checked without trusting the narrative | Claim-level source passage/table or execution observation, stable source version and rights decision; support and contradiction both retained. Missing source becomes UNKNOWN; metadata-only remains explicit |
| Independent-method agreement and confidence | Customers can distinguish corroboration from duplicated assumptions | Extend the presentation of Sol S11a AgreementRecord, without replacing it: name the estimand, units, method/version, data origins, shared training data and assumptions, uncertainty and discrepancy. Count methods by independence groups, not API brands. Compare only compatible endpoints; no naive probability multiplication or universal confidence score. Calibrate any probabilistic confidence on held-out reference cases, report coverage/error and keep conflicts |
| Cross-domain ResearchRun with Scientific Worlds inspection | One audit method works across bounded domains while a visual view helps inspect location, time and uncertainty | Same canonical lifecycle/export for the primary chemistry task and one secondary PySCF or physics case after the primary passes. Worlds display linked records, units, provenance and UNKNOWN states; camera/animation changes neither evidence nor protocol |

For independence, reuse `sourceIndependence.mjs`: a ChEMBL assay mirrored through PubChem is one observation, not corroboration. Repeated samples from one model do not establish independent scientific evidence. Docking energy, predicted activity and clinical outcome are different estimands; agreement must not be manufactured by normalizing them into a single winner score. When independence or calibration is unknown, show method-level results and disagreement without an aggregated confidence claim.

## What not to do now

- Do not create a second ResearchRun lifecycle, evidence database, solver registry or generic queue framework. Extend the inspected contracts and preserve IDs.
- Do not start whole-corpus scraping, a universal vector index or foundation-model training before one licensed query-to-report path passes.
- Do not purchase GPU capacity or adopt Kubernetes/multi-region complexity before measured workload, operations ownership and failure recovery justify it.
- Do not expose arbitrary generated code or rely on a container, timeout or worker thread as proof of a secure sandbox.
- Do not soften the GLP-1R validation gate, merge binding with functional agonism to force a pass, relabel D-152 as model validation, or count mirrored assays as independent evidence.
- Do not turn matching methods into invented confidence, docking into efficacy, visualization into biology, or a secondary H2 example into general quantum-science validation.
- Do not bulk-clear PubChem, HPA, NIST, publication text, model weights or private data based on their provider's name or code licence.
- Do not let Astra implement Claude/Sol code, promise deployment, alter historical sealed evidence, or publish unsupported enterprise/clinical/market claims.
